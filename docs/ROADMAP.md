# KeyboardBridge — 技术路线与阶段计划

## 1. 目标和非目标

**目标：** 利用 Windows 键盘，在 HarmonyOS 7 手机第三方日记 App 当前编辑框中舒适、可靠地输入简体中文，并优先通过可信局域网无线连接。

**不做：** 新日记 App、导入导出私人日记、跨公网控制、云同步、AI 写作、聊天服务、iPad 首期客户端、通用手机远程控制平台。

成功的 MVP 是：用户主动连接并在手机选中编辑框后，电脑输入正确落入手机文本框；异常时可发现、可恢复，不会自动重复提交。

## 2. 路线决策表

| 候选路线 | 前提 | 需要证明 | 决策 |
| --- | --- | --- | --- |
| A. 原生键鼠共享 | 具体品牌和型号组合受支持 | 非华为 Windows 电脑能实际建立连接，第三方 App 中中文正常 | 通过则优先免开发 |
| B. HDC + `uitest` 文本提交 | 真机开放 HDC 与无线调试，且零售机存在 `uitest` | 中文提交、标点、回车、光标、稳定性 | **模拟器已验证中文提交**；真机待验证，通过即首选 |
| B2. Android scrcpy / ADB | — | — | **已排除**：API 26 无 adb 二进制 |
| B3. `uinput` 键盘模拟 | — | — | **中文不可行**：仅支持 ASCII |
| C. 自研 Windows + HarmonyOS 端 | 官方公开输入法/文本提交机制可用 | 第三方 App 真实文本框提交的最小 PoC | A/B 不满足时才尝试 |
| D. 主动复制粘贴 | 用户可主动触发粘贴 | 中文长文本、换行和恢复可用 | 平台限制下的保底方案 |

**切勿推断：** Android 支持某工具 ≠ HarmonyOS 7 一定兼容；能接收网络数据 ≠ 有权修改任意第三方 App 文本；输入事件被发送 ≠ 日记已保存。

## 3. 阶段计划

### Phase 0 — 先验证
- 只读核对仓库和开发环境；确认手机型号、真实系统版本、调试入口与权限（在本地记录，避免公开敏感标识）。**已完成**，见 [PHASE0-AUDIT.md](PHASE0-AUDIT.md)。
- 查阅 scrcpy、HDC、UiTest、uinput 官方资料并记录出处及日期。**已完成一部分**，见 [PHASE0-HDC-SPIKE.md](PHASE0-HDC-SPIKE.md)。
- **模拟器已确认** HDC 可提交中文；**当前唯一阻塞**是零售真机验证。下一步在真机上运行 `scripts/Test-DeviceBridge.ps1 -Inject`。
- 如无法无线调试，记录是否允许首次 USB 配对作为可选尝试，避免直接转向高成本自研。
- 产物：docs/VALIDATION.md 中测试矩阵和可复现结论。
- **退出条件：** 选定可行路线，或对失败/未知给出准确的阻塞点。

### Phase 1 — 最小 Windows 体验
仅在需要时开始。
- 连接/断开、状态、错误提示、可撤销授权。
- 已验证方案的启动和配置封装；必要时增加按需手动输入/发送功能。
- 不添加内容存储、自动同步、云服务。
- **退出条件：** 真机中文输入通过，网络异常处理有记录。

### Phase 2 — 鸿蒙端原型（条件触发）
- 仅在官方 API 核实且路线 A/B 未满足时启动。
- 先写单一输入法/接收器 PoC，证明合法输入第三方 App，再考虑通信、UI、打包。
- 若输入法无法建立可靠提交语义，退回用户确认/手动粘贴模式。
- **退出条件：** 真实目标 App 的最小输入链路成功，并有可回退说明。

### Phase 3 — 质量和交付
- 中文长文本、网络抖动、重复事件、锁屏、前后台切换的可靠性测试。
- 安全审计：暴露面、身份验证、传输保护、日志及凭据处理。
- 发布 Windows 安装包和（若必要）鸿蒙安装包，文档覆盖卸载/回退。
- **退出条件：** 核心验收项通过，剩余限制公开且可接受。

## 4. 架构草案（未定案）

```text
Windows keyboard
      |
      v
[可选 Windows 启动/连接助手]
      |
      +--> 已验证的系统键盘共享/键盘模拟 ------> 手机当前焦点输入框
      |
      +--> 条件方案：局域网配对与受保护通信
                      |
                      v
             [HarmonyOS 接收端/官方输入法扩展]
                      |
                      v
               第三方 App 编辑框
```

不默认采用 TCP/WebSocket，也不默认采用 Electron/Tauri/.NET；应依据现有环境、真实设备 API、维护成本和二进制体积作最小选择。

## 5. 关键风险

- **系统兼容性：** 鸿蒙设备不一定支持 Android ADB/UHID。
- **输入法：** 网络接收与输入提交权限可能分属不同进程或受平台限制。
- **中文输入：** 物理键盘模式和手机当前中文 IME 的候选词行为需实测。
- **重复输入：** 传输 ACK 不代表第三方 App 已接收或保存文字。
- **隐私：** 日记内容不得写入调试日志、Git 仓库或远端服务。
- **目标 App：** 不同编辑器可能限制外接键盘、粘贴、自动保存。
